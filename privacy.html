Natasha / Privacy

Privacy policy

Last updated: 6 October 2026

Natasha is a personal Gmail assistant operated by Benjamin using OpenClaw hosted by MyClaw. This policy covers that integration and this public information website. The integration is intended solely for the owner’s own Gmail account.

Google account access and information

Natasha connects using Google OAuth, with the permissions approved by the account owner. Depending on those permissions and the task, the integration can access the account email address, message subjects and contents, sender and recipient details, message dates, thread information, labels and attachments.

If write permissions are granted, actions can include preparing drafts, sending messages and changing messages or labels. The Google consent screen describes the access requested. Google authorization does not require sharing the account’s Google password with Natasha.

Purpose of processing

Google user data is used to perform the owner’s personal email-assistance tasks, such as finding messages, summarising information, preparing replies and carrying out configured email actions. Information included in a task can appear in prompts, responses and saved work generated by the assistant.

MyClaw and AI processing

The integration runs in the owner’s cloud-hosted MyClaw environment. Relevant email content and task instructions may be sent through MyClaw to the configured AI service to generate a response. The owner currently identifies the configured model as GPT 5.6 Luna.

Cloud hosting, AI processing and any intermediary routing are subject to the services and account settings used by MyClaw and the owner. This policy does not make a zero-retention claim for those providers.

Storage and retention

OAuth credentials and tokens are kept in the cloud environment’s credential storage; the configured token store uses an encrypted keyring. Email text, summaries and other task information may remain in conversation history, saved files, logs or backups where those features are enabled.

Retention and deletion of these copies depend on the configured storage, logs and service-provider settings. Revoking Google access stops further authorized access through that grant; it does not by itself erase previously stored conversations, files, logs or backups.

Limits on use and sharing

Google user data is to be used only for the personal assistance described here. It must not be sold, used for advertising, or used to develop or improve general-purpose AI models. Transfers to service providers must be limited to what is needed for those assistance functions, with the account owner’s authorization, or other uses permitted by Google’s policy.

Natasha’s use and transfer of information received from Google APIs must adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Control, removal and contact

The owner can review or remove the integration from Google Account connections, disconnect the Gmail account in the cloud environment, and remove retained assistant records using the relevant service controls. Provider-held copies and backups may need separate deletion requests and may be subject to provider retention obligations.

For questions or a request concerning information handled by Natasha, contact benjaminsmiff1978@gmail.com. Do not include passwords, access tokens or OAuth client-secret files in a request.

This public website

This website contains information pages. It has no Google sign-in, Gmail connection, forms, advertising or analytics scripts. Visiting it does not give the website access to Gmail.

GitHub Pages hosts the published website. GitHub states that it logs visitors’ IP addresses for security purposes. See the GitHub Privacy Statement.

Changes

This policy should be updated before Natasha’s data practices change. Any new access or use requiring consent must be presented to the account owner before it begins.
